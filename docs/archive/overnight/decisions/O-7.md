## Item 1: NestJS 11 vs 12

| Option | Pros | Cons | Impact |
|---|---|---|---|
| A. Confirm 11 | stable, what everything was built and tested with tonight; no upgrade risk before the maturita | the structure doc is out of date | doc change only |
| B. ## Item 2: own `ZodValidationPipe` vs `nestjs-zod`

| Option | Pros | Cons | Impact |
|---|---|---|---|
| A. Keep the own pipe | 21 lines anyone can read and explain; works directly with the **generated** `z*` schemas; error shape fully controlled (RFC 9457) | reports only the first issue; no DTO classes for Swagger (not needed: docs come from `openapi.yaml`) | none |
| B. Switch to `nestjs-zod` | `createZodDto`, multi-issue errors, community-maintained | extra dependency; its error format must be mapped to `ErrorDetails` anyway; Swagger integration is irrelevant with spec-first | controllers' `@Body(...)` change; tests unchanged (they test HTTP) |
| C. Keep the own pipe, extend it | can report all issues (`errors[]` extension) if the frontend needs it | spec change if a new field is added to `ErrorDetails` | pipe + spec |

Related: R-015 (a generated schema loses `required`). That is a generator issue and happens with either pipe.
